## 0. 结论摘要（TL;DR）

**allClear = false — 不发布。** 遗留项修完并 browser 复验通过前，PRD-0010 无 Shipped 资格。

本轮最硬的事实：**AE / BE / CE 三个 wave 的全部 browser-driven E2E 均被环境阻断** —— Claude Chrome 扩展未与本 session 配对（`list_connected_browsers` 恒返回 `[]`，四个纬度 subagent 各自独立确认 + critic 复确），因此**没有任何一纬取得"浏览器可见 + DOM 二确"证据**。按 E2E 铁律 backend artifact / REST / SQLite / 代码阅读均不算 E2E 通过，故三个 completeness-critic 全部判 `pass=false`。**这是 harness 侧阻断，不是产品缺陷**：

- `curl http://localhost:3271/` → **HTTP 200**；`/api/works` 正常返回 work 列表。
- dist 新鲜（`dist/index.js` / `web/dist/index.html` mtime 均晚于最新 commit）、daemon 健康（PID 40418 LISTEN :3271）、codex 已登录（ChatGPT 模式，`~/.codex/auth.json` 有 tokens）。
- 阻断唯一原因：浏览器扩展未连接，subagent 无法自行发起需真人点 Connect 的配对流程。

**但浏览器阻断没有让本轮颗粒无收** —— backend / CLI / grep 层揪出并修复了 **1 个 CRITICAL 真缺陷**（BE3-F1，账本即事实源、无需浏览器即成立，已 fixed-verified）+ 若干 code-confirmed gap（详见 §5）。

## 11. BE2-F1 三修与终验（2026-07-06）

第二轮唯一阻塞是 **BE2 画布聚簇 F1**（Provenance Dive 画布内簇标题跳转 / 未归属折叠 toggle / take 的 USE 选用三处控件对**真实鼠标点击**全部失效），前两次修复（`ab2599a` → `90c0300`）落代码后 browser 复验仍失败。本节记录第三修的根因诊断、修复与浏览器终验，**本节为本报告最终结论，取代 §8/§10.8 的"跳过收官"判定**。

### 11.1 codex 独立诊断 —— 揪出被两次修复漏掉的第二重机制

前两修都只做了一件事：给三处控件补 `pointer-events: auto`，把它们从 `pointer-events:none` 的祖先里"重新变成命中目标"。但真鼠标点击依旧死。**codex 独立诊断**定位到 xyflow 有**两重**独立机制在吞点击，前两修只解了第一重：

1. **命中目标机制（前两修已解）**：簇组节点 `draggable:false` → xyflow 的 `NodeWrapper` 给 `.react-flow__node` wrapper 打 `pointer-events:none`，内部 `<button>` 继承 none。补 `pointer-events:auto` 让按钮重新可被命中。
2. **pane pan 抢占机制（第三修才解）**：xyflow 的画布平移/缩放是绑在 `react-flow__pane` 上的 d3-zoom；其 filter（`@xyflow/system` 的 `createFilter`）**只有当 pointerdown 的 target 被 `nopan` class 包裹时才放行不启动平移**。而 xyflow **只给 draggable 的 node wrapper 打 `nopan`**（`NodeWrapper` 的 `[noPanClassName]: isDraggable`）——簇组节点 `draggable:false`，wrapper 既是 `pointer-events:none` 又**不带 `nopan`**。于是真鼠标 pointerdown 一落到控件上就立刻被 pane 抢去发起画布平移，把随后的 `click` 吃掉。**这就是为什么哪怕 dist 是新的、控件已是命中目标，真实点击依旧死**——而单测里的 `fireEvent.click` 直接派发合成 click、绕过命中测试与 pointerdown→pan 这条链，所以一直假绿。
