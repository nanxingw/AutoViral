# PRD-0012 · 导出保真与成品管理

## Problem Statement

用户（创作者，用 Seedance 生成素材、在 Studio 完成剪辑后导出成片）面对两个直接伤害交付的问题：

1. **成片抽动，不可交付**。导出的最终视频平均每 ~3 秒出现一次"画面跳回前几帧"（帧级取证：106s 成片 37 处倒跳、回跳 2–12 帧，烧进文件本身）。源片经同法扫描为 0 处——抽动是渲染管线引入的，与画布 fps 无关（24/30fps 成片同病、事件位置重合）、与转场无关（事件全在 clip 中段）。根因：预览与服务端导出共用同一棵视频组件树，而组件无条件使用原生视频标签做逐帧 seek——原生 seek 非帧精确，在 Seedance 源片 ~1 秒一个关键帧的编码下，seek 落到更早的关键帧就是"跳回前几帧"。此外还有两个放大项：为预览体验放宽到 1.2s 的 seek 容差同样作用于导出；裁剪/变速等 ffmpeg 预处理重编码时不设关键帧间隔，会把源片的 1s GOP 归一抹成 ~10s（潜伏雷，当前作品未触发）。
2. **成品和素材混在一起，导出完就"丢"**。素材库的数据源是目录扫描且把导出目录一起扫进来：一次导出实际产生 4–5 个 mp4（渲染中间产物不清理），全部落进素材库 CLIPS 分组与源片混排；而导出进度弹窗一旦关闭，UI 里没有任何入口能再次找到成片——用户只能回素材库大海捞针，或去文件系统翻目录。

## Solution

**A · 导出保真（修抽动）**：让渲染环境决定视频组件——服务端导出走帧精确的离线抽帧组件（无头渲染没有"多路隐藏 video 耗尽解码器预算"的预览顾虑），浏览器预览保持现有原生组件（5 月 8 日为解码器预算问题所做的优化不回退）；预览专属的 seek 容差参数只在预览分支下发。同时给所有 ffmpeg 预处理补关键帧间隔归一（对齐 Seedance 归一先例），拆掉潜伏雷。把本次调查用的帧级倒跳取证脚本收编为仓库 QA 工具，作为修复验收与未来回归的客观标尺。

**B · 成品管理（好找）**：素材库把导出成品拆成独立「成品」分组、过滤渲染中间产物（复用既有管线内部文件过滤器的机制），一次导出在库里只出现成片与代理两个条目；服务端渲染完成后清理中间产物；补一个导出历史入口（后端队列已有全部数据，缺列表端点与 UI），关掉进度弹窗后成片始终找得回。

用户视角的最终状态：导出的片子帧序干净（取证扫描 0 倒跳）；素材库里「成品」独立成区一眼可辨；任何时候都能从导出历史里重新下载/定位历史成片。

## User Stories

1. As a 创作者, I want 导出的成片不再出现画面跳回前几帧的抽动, so that 我可以直接把片子交付/发布。
2. As a 创作者, I want 预览的流畅度保持现状, so that 修导出问题不以牺牲编辑体验为代价。
3. As a 创作者, I want 用了裁剪/变速/倒放的片段导出后同样帧序干净, so that 高级编辑功能不会引入新的抽动。
4. As a 开发者/QA agent, I want 一个客观的帧级倒跳检测工具, so that "导出是否干净"由数据判定而不是肉眼感觉。
5. As a 创作者, I want 素材库里成品与源素材分区展示, so that 我找成片时不用在源片堆里翻。
6. As a 创作者, I want 渲染中间产物不出现在素材库, so that 一次导出不会往库里塞四五个长得一样的视频。
7. As a 创作者, I want 关掉导出进度弹窗后仍能找回成片（下载/在 Finder 显示/预览）, so that 我不必为了保住入口而不敢关弹窗。
8. As a 创作者, I want 看到历史导出列表（时间、preset、文件）, so that 我能对比多次导出的版本并取回旧版。
9. As a 创作者, I want 成品条目有明确的视觉标识（成片徽章/导出时间）, so that 它们和素材 tile 一眼可辨。
10. As a 工位 agent, I want 成品与素材在数据投影上可区分, so that 我能程序化地定位"最新成片"而不是猜文件名。
11. As a 创作者, I want 渲染管线的行为变化有回归测试锁住, so that 抽动这类回归不会再静默复发。

## Implementation Decisions

- **渲染环境分支（核心修复）**：视频轨渲染组件按 Remotion 渲染环境判定分支——服务端渲染（含 streaming 路径）用离线抽帧组件（帧精确），浏览器预览保持原生视频组件；预览专属的 seek 容差与缓冲参数只在预览分支下发。不引入新的组件抽象，只在现有组件内部分支。
- **预处理关键帧归一**：裁剪/翻转、timewarp、变速三个 ffmpeg 预处理的重编码统一补关键帧间隔 = 帧率（≈1s GOP），对齐 Seedance 入库归一的既有先例；参数以 argv 断言锁住。
- **取证工具入库**：帧级倒跳扫描脚本（灰度指纹 + "与前 1 帧差异大却与前 k 帧近同"签名）收编为仓库脚本工具，文档化用法；修复验收与 E2E 导出纬引用它。
- **成品分组（纯前端）**：素材分组逻辑把导出目录下的成片/代理拆为独立「成品」分组；渲染中间产物（Stage1 输出与各 stage 派生文件）加入既有管线内部文件过滤器，不再展示。分组为纯函数，可隔离测试。
- **中间产物清理（服务端）**：渲染管线成功产出最终文件后删除本次派生的中间 mp4；失败路径保留现场以便诊断。
- **导出历史**：渲染队列已有持久化 store（含输出路径），补一个按 work 列出历史 job 的端点；UI 在导出入口附近提供历史列表，复用现有"下载 / 在 Finder 显示 / 预览"三入口。
- **成品视觉标识**：成品条目带成片徽章与导出时间（editorial 语汇：mono 时间戳），与素材 tile 区分。

## Testing Decisions

- **好测试的定义**：只测外部行为——"渲染环境下选离线抽帧组件"、"预处理 argv 含关键帧参数"、"分组函数把 output 成片归成品组、中间产物被过滤"、"渲染成功后中间文件不存在"；不断言组件内部实现。
- **组件分支测试**：mock 渲染环境标志，断言两个分支各渲染哪个组件、预览专属 props 只出现在预览分支。先例：composition 目录下既有的 track renderer 结构测试。
- **预处理 argv 测试**：spawn mock 捕获 ffmpeg 参数断言含关键帧间隔。先例：render-pipeline 的 spawn-mock 测试（注意沿用 drain-until-settled 模式，勿回退固定轮数）。
- **分组/过滤纯函数测试**：先例：既有管线内部文件过滤器的单测。
- **中间产物清理测试**：mock fs 断言成功路径删除、失败路径保留。
- **导出历史端点测试**：先例：render 路由既有测试 + `:memory:` SQLite 注入（render-queue 模式）。
- **终极验收（客观标尺）**：对取证 work 重新导出，jitter-scan 倒跳事件 = 0（源片扫描同法为基线）；此项写进对应切片的 Acceptance criteria。
- **E2E 验收纬度预写**（实施后按 e2e-testing.md 派 Workflow，主 agent 不亲跑）：① 导出纬——真实导出 + ffprobe/jitter-scan 数据判定；② 预览纬——播放流畅性不回退；③ 成品查找纬——导出→关弹窗→从成品分组/历史找回并下载的完整用户路径；④ 中间产物纬——导出后素材库新增条目 ≤2。

## Out of Scope

- **Seedance 源片改 all-intra 编码**：修复组件分支后 1s GOP 已够；all-intra 体积代价大，无必要。
- **渲染性能优化**（并发、缓存大小调优）：离线抽帧组件的缓存参数只做保守显式化，不做性能专项。
- **导出文件命名规则重设计**：保持现有命名，成品管理靠分组与历史解决。
- **跨 work 的全局成品库**：本 PRD 只做单 work 内的成品分区与历史。
- **画布 fps 相关**：归 PRD-0011。
