# PRD-0010 · v0.1.8 工作台可信度与全貌升级

## Problem Statement

用户（创作者，在 Studio 里与 agent 协作出片）当前面对六个信任与感知损耗：

1. **Chat 消息经常重复/错乱**。同一条消息出现两份、消息短暂消失又回来——用户无法信任对话记录是"真的发生过的事"。磁盘铁证：存在同一条 user 消息完整落盘两份的 work（相隔 13.6s），且第二次发送还会误杀正在流式输出的 CLI 进程。
2. **Chat 只能用 Claude**。Terminal 面板早已 agent-agnostic，但低认知负荷的 Chat 面板锁死 claude——"任何 CLI agent 都能驱动"的产品命题在最常用的入口上不成立（CONTEXT.md 自认 acknowledged gap）。
3. **花了多少钱没处看**。生成一条片花掉的 agent token、生图、生视频、TTS、翻译成本分散甚至根本没记（生图 usage 被整个丢弃、agent 成本刷新即归零、TTS/翻译零记账），用户无法在制作过程中自己判断投入产出。
4. **剧本·分镜面板不可读**。剧本以裸 markdown 显示在 ~140px 小框里（`#`、`>` 全裸奔），预览态存在但默认藏着、样式类名是死的、不渲染 GFM、高度锁 320px；右栏默认 ~245px 宽，分镜摘要行的标题被 meta 挤成零宽省略号。
5. **素材库音频/文字卡片误导**。所有素材共用 9:16 竖版渐变大卡，音频只有一个喇叭图标、文字素材连内容分支都没有——看起来全像图片封面，一屏只放得下 2-4 张；更糟的是 TEXT 分类里混着 `.peaks.json`、`concat.txt` 等管线内部文件伪装的"素材"。
6. **作品全貌无处感知**。衍生图谱（Dive）只画平铺 asset DAG，与分镜无关联；用户无法一眼看到"每个分镜用到了哪些素材、哪个 take 被选用、哪些镜已过期"。且 i2v 生成不记录 firstFrame 来源，定妆照→视频这条主力工作流的衍生关系在图上全是断链。

## Solution

v0.1.8 围绕"**可信**（消息不重复、成本有账）与**全貌**（剧本可读、素材可辨、分镜聚簇画布）"做六个切片：

- **S1 Chat 消息流根治**：给每个消息块发稳定身份（server 分配 id 穿透全部持久化/重放/实时路径），前端按 id upsert；发送加锁、断线禁发、服务端幂等窗——重复从"启发式压制"变为"结构性不可能"。
- **S2 Codex Chat 后端（完整 parity）**：抽 ChatBackend 接口，Chat 面板可按会话选择 Claude 或 Codex 驱动，viewer-context / viewer-action / checkpoint 全支持；认证由用户在 Terminal 跑一次 `codex login` 自理，Chat 侧只做检测与引导。
- **S3 Per-work 成本展示**：全局 SQLite 成本账本 + 六路埋点（视频/生图/BGM/TTS/翻译/agent 会话），展示聚焦**作品制作页内**——Studio/Editor 顶部成本徽章「本片 $X」，点开按类型分解明细，估算值诚实标注。不做审批门、不打断创作。
- **S4 剧本·分镜可读性**：预览成为默认态并真正渲染（编辑部样式 + GFM + 高度自适应），加全屏阅读/编辑 modal（~720px 阅读列宽），分镜摘要行窄栏降级 + 右栏可拖更宽。
- **S5 素材库 per-kind 卡形分家**：音频改紧凑横条（就地播放 + 迷你波形 + 时长），文字改内容 snippet 卡，管线内部文件过滤出素材库，一屏音频密度 2-4 → 10+。
- **S6 Dive 分镜聚簇无限画布**：升级为按 scene 聚簇的全貌感知层（xyflow group node + 视口裁剪），只读浏览 + 保留 USE THIS 换 take + 点簇跳转分镜卡；补上 i2v firstFrame→视频的 provenance 断链。入口提升到 Studio 顶栏。

## User Stories

### S1 · Chat 消息流

1. 作为创作者，我希望我发出的每条消息在对话里只出现一次，这样我能信任对话记录。
2. 作为创作者，我希望刷新页面或断网重连后对话历史与刷新前一致（不多、不少、不乱序），这样我不用怀疑自己看到的是不是真的。
3. 作为创作者，我希望网络断开时发送按钮明确不可用并提示我，而不是静默吞掉或排队重发，这样我不会无意间发出两份。
4. 作为创作者，我希望连击发送/回车不会把同一条消息发两次，也不会误杀正在回答的 agent。
5. 作为创作者，我希望 agent 回答到一半时我打开面板，看到的是最新进度而不是"闪回旧状态再跳回来"。
6. 作为 CLI agent（经 bridge 读 chat 历史），我希望持久化的每个消息块带稳定 id，这样我重放/对账时能精确定位。
7. 作为维护者，我希望"新增消息块字段必须穿透全部 seed 路径"从教训变成被测试锁住的验收项。

### S2 · Codex 后端

8. 作为 power user，我想在新建 Chat 会话时选择用 Claude 还是 Codex 驱动，这样我能用自己订阅/偏好的 agent。
9. 作为创作者，我希望 Codex 驱动的 Chat 与 Claude 有同等体验——能读到我的界面焦点（viewer-context）、能驱动 Studio 跳转（viewer-action）、每轮自动打 checkpoint。
10. 作为创作者，我希望切换后端时被明确告知"这是新对话、旧上下文不带过去"，而不是悄悄丢上下文。
11. 作为 power user，我希望 Codex 的认证复用我在终端里已有的 `codex login` 登录态，AutoViral 不另管我的 OpenAI 凭证。
12. 作为创作者，若我未登录 Codex，我希望 Chat 给出友好引导（怎么登录）而不是一段 ENOENT 报错。
13. 作为创作者，我希望 Codex 会话也显示用量（token 数），即使它不提供美元成本——宁可少显示也不显示编造的换算价。
14. 作为维护者，我希望 Claude 与 Codex 的差异被封在一个后端接口后面，将来加第三家（kimi/gemini CLI）不用再改消息管线。

### S3 · Per-work 成本

15. 作为创作者，我想在作品制作页看到"本片到现在花了多少钱"，这样我自己判断投入是否值得——不需要系统替我审批或打断我。
16. 作为创作者，我想点开成本徽章看到分解：agent 会话花了多少、生图多少、生视频多少、TTS/配乐/翻译多少。
17. 作为创作者，我希望估算出来的数字（拿不到真实账单的调用）被明确标注"估算"，这样我知道哪些数字可信到什么程度。
18. 作为创作者，我希望 agent 会话的花费在刷新页面后仍然在，而不是每次归零。
19. 作为图文作者（Editor 页），我同样想看到本作品的生图成本。
20. 作为创作者，我希望记账永远不阻断生成——记账失败最多丢一条账，不能让我的片生成失败。
21. 作为维护者，我希望所有付费调用经过单一记账入口，新 provider 接入时自然带上记账。

### S4 · 剧本·分镜

22. 作为创作者，我打开剧本·分镜 tab 时希望首先看到**排版后的剧本**（标题、引用、表格都渲染好），而不是裸 markdown 源码。
23. 作为创作者，我想一键进入全屏阅读模式，用舒适的行宽和字号通读整个剧本。
24. 作为创作者，我想在全屏模式里直接编辑剧本并保存，保存路径与 agent 改剧本是同一条。
25. 作为创作者，我希望系统记住我上次选的是预览还是编辑态。
26. 作为创作者，右栏较窄时我希望分镜行优先保住标题可读，次要 meta（时长/景别/意图）自动让位。
27. 作为创作者，我希望能把右栏拖得更宽来舒服地读剧本，且下次打开还保持我拖的宽度。

### S5 · 素材库

28. 作为创作者，我希望音频素材一眼就能认出是音频——波形、时长、播放按钮，而不是一张像图片封面的渐变卡。
29. 作为创作者，我想在素材列表里直接点播放试听（同一时刻只播一个），不必先打开预览弹窗。
30. 作为创作者，我希望文字素材卡直接显示内容开头几行，这样我不用点开就知道是哪份文案/字幕。
31. 作为创作者，我希望素材库里只出现真正的素材——波形缓存、拼接清单这类管线内部文件不要伪装成素材误导我。
32. 作为创作者，我希望一屏能看到 10+ 条音频而不是 2-4 张大卡。
33. 作为创作者，点开文字素材预览时我想看到全文而不是一个死链接卡。
34. 作为 CLI agent，素材库 UI 的过滤不应影响我经 bridge 看到的完整文件列表。

### S6 · 聚簇画布

35. 作为创作者，我想打开一张"全貌图"：每个分镜一个簇，簇里是它的所有 take 和素材，选用的 take 高亮——一眼看清整部片子的生产状态。
36. 作为创作者，我希望簇标题显示镜号、标题、意图、景别和状态（含"需重生"），和分镜列表同一套语言。
37. 作为创作者，我想点击簇标题跳回剧本·分镜 tab 对应的分镜卡去操作——画布负责看，操作留在既有面板。
38. 作为创作者，我想在画布上继续用 USE THIS 把选中 clip 换成另一个 take。
39. 作为创作者，我希望不属于任何分镜的素材（上传、BGM、对话框生成）收进一个默认折叠的"未归属"簇，而不是散落满图。
40. 作为创作者，我希望定妆照→i2v 视频的衍生关系在图上是连着的，这样我能追溯"这条视频是从哪张定妆照来的"。
41. 作为创作者，我希望画布在几百个素材的 work 里依然流畅（视口外不加载视频）。
42. 作为创作者，我想在"按分镜聚簇"和"按衍生链"两种视角间切换——变体系谱追溯仍然有用。
43. 作为创作者，我希望画布入口在 Studio 顶栏显眼处，而不是藏在 Inspector tab 深处。
44. 作为 CLI agent，我生成的资产若带 scene 归属，希望它自动出现在对应簇里（与 UI 生成同一套关联语义）。

## Implementation Decisions

### S1 · Chat 消息流根治（约 2.5 人日）

- **稳定块身份是根治，不再加启发式**：ws-bridge 在消息块进入 messageHistory 时分配单调稳定 id（`{sessionId}:{seq}` 形态），chat 日志落盘带 id，HTTP history / WS history 重放 / WS 实时块三条 seed 路径全部携带同一 id。
- **前端 store 改 by-id upsert**（Map + 顺序数组）；无 id 的旧日志行按行号合成兜底 id（照 loadWorkChat 已有的逐行归一先例）；保留现有"末块启发式"仅作旧 server 兼容 fallback。
- **发送锁**：submit 加 useRef in-flight 锁（照 #62 export double-fire 修复先例）；WS 非 open 态禁发并提示（复用 ReconnectingWS 已有状态广播）。
- **服务端幂等窗**：同 session、CLI in-flight、文本全等、≤3 秒内的重复 user 消息拒绝二次入账——窗口收紧以免误吞用户故意连发的相同短句。
- **seed 收敛**：默认会话的 history 读取改 jsonl-first（json 快照仅作旧数据 fallback），消除 mid-turn 陈旧快照吞新块的竞态。
- 既有教训"新 StreamBlock 字段必须穿全部 seed 路径"升级为本切片验收项与回归测试。

### S2 · Codex Chat 后端（约 3.5-4 人日）

- **ChatBackend 深模块**：接口两件事——`buildSpawn`（组装命令/args/env：prompt、resume id、补教学、model）+ `createLineParser`（流式行 → onSessionId / onText / onThinking / onToolUse / onToolResult / onTurnComplete 统一事件）。Claude 实现为现有逻辑平移；Codex 实现基于 `codex exec --json`（JSONL 事件）与 `codex exec resume`。解析归一到 ChatBlock 后，下游持久化/广播完全 backend 无关。
- **完整 parity 而非降级版**：viewer-context 信封（前端 prepend 纯文本）、viewer-action tag（前端从 assistant 文本正则解析）、checkpoint（服务端 turn 钩子）三者本就 backend-agnostic——Codex 版只需 system prompt 补 viewer-action 语法章节，并把 Claude 专属的 `Skill('autoviral')` 指引改为 `autoviral docs`。
- **落地前先实测锚定** codex `--json` 事件 schema，做成 fixture 进单测（事件命名有版本变动史）。
- **后端选择为 per-session 属性**存 SessionRecord（复用 cliSessionId 字段作通用 resume id + 新增 backend 字段），全局默认值兜底；切换机制复刻 model switcher 的 killSession+respawn 模式；跨后端 resume 不互通 → 已有会话不可切后端，新会话选择，UI 明示。
- **认证（用户拍板）**：`codex login` 自理——spawn 前检测登录态（auth 文件/一次探测），未登录时 Chat 给引导文案（到 Terminal 面板跑 `codex login`）。AutoViral 不管理 OpenAI 凭证。
- **权限对齐现状**：Codex 以等价于 Claude `--dangerously-skip-permissions` 的全放开模式跑（本地单用户工作站哲学），沙箱收紧另议。
- **成本诚实降级**：Codex 无美元成本回传，turn 用量只显示 token，不做本地价格表折算。
- **范围**：仅 work chat。coach / trends / cli-brief 三个次要 Claude 面保持 claude（trends 有 WebSearch 工具名匹配等额外耦合）。ENOENT 报错文案 per-backend。
- **文档配套**：新 ADR-013（Chat 多后端架构）+ CONTEXT.md 不变量 #4 的"deferred to 0.2.0"措辞更新为已落地。

### S3 · Per-work 成本展示（约 3.5-4 人日）

- **cost-ledger 深模块**：SQLite 账本（复刻 render-queue 的 defaultDbPath / schema-in-code / `:memory:` 测试注入模式），表结构 `cost_events(id, ts, work_id, kind, provider, model, usd, estimated, meta)`。单一 `recordCostEvent()` 入口，**best-effort：记账失败绝不阻断生成**。
- **六路埋点**：视频与 BGM 的资产注册点；生图路由（请求补 `usage: {include: true}` 换取 OpenRouter 真实成本回传，**并顺带补上图片的 provenance 注册**——目前图片连 provenance edge 都没有，此项与 S6 数据补链共享改动面）；TTS 两条路由；文案改写/翻译；agent 会话 result 帧。
- **estimated 诚实标记**：拿不到真实价的调用（BGM 文档平价、TTS 估价）入账必须 `estimated: true`，UI 显示"估算"徽标；agent 成本入账前必须实证 resume 会话的 total_cost_usd 是否累计值并取 delta（已有代码注释警告过此 gotcha），否则重复计账虚高。
- **agent 成本持久化**：ChatBlock 增加 usage 字段，turn 结束时写进最后一个 text 块并落盘——该字段必须穿透全部三条 seed 路径（S1 的验收纪律直接适用）；会话累计不再刷新归零。
- **展示（用户拍板：制作页内 per-work，不做全局页）**：Studio 顶栏成本徽章「本片 $X」→ 点击展开明细面板（按 kind 分解 + estimated 标注 + agent token 用量）；Editor（图文）同款徽章。数据经 per-work 汇总查询端点。
- **历史口径**：从 v0.1.8 起记新账；视频/BGM 可从既有 provenance 的 costUsd 扫描回填，其余类型历史无据——明细面板注明口径起始，不假装完整。

### S4 · 剧本·分镜可读性（约 2-2.5 人日）

- **预览为默认态**（剧本非空时；空剧本默认编辑态），手动切换用 localStorage 记忆（照 script fold 折叠偏好先例）。
- **预览真正渲染**：复用全局 `.md-bubble` 编辑部样式（p/code/h1-h4/blockquote/table 全套现成）替换死类名；挂 remarkGfm；去掉 320px 高度锁改 flex 自适应。
- **共享 Markdown 深模块**：把 Chat 的 ReactMarkdown + remarkGfm + md-bubble + 资产 URL 翻译三件套抽成共享组件，Chat 与剧本预览双端复用，杜绝第三处再抄。
- **全屏阅读/编辑 modal**：照同目录 AssetPreviewModal 惯例（portal 到 body——glass 祖先 backdrop-filter 是 fixed 定位陷阱，已验证路径）；~720px 阅读列宽 + 15-16px 字号；modal 内同款编辑/预览 toggle；写路径复用现有 blur 提交（与 agent `script edit` 同路径）。编辑器保持朴素 textarea，不引入高级 md 编辑器。
- **窄栏降级**：分镜摘要行的 meta 段按优先级隐藏保标题可读（信息在展开 Inspector 内仍可达）；右栏 maxSize 从 28% 放宽至 ~40%（拖动结果已有持久化）。

### S5 · 素材库 per-kind 卡形分家（约 2 人日）

- **布局按 kind 分家**：CLIPS/IMAGES 保留 9:16 两列网格；AUDIO 换 ~52px 紧凑横条（播放/暂停钮 + 迷你波形 + mono 时长 + 文件名，现有 ＋/删除/拖拽 affordance 原样保留）；TEXT 换内容 snippet 卡（取文件前 ~200 字符，mono 3 行 clamp + 扩展名徽章）。
- **波形零后端成本**：复用 peaks sidecar 快路径（server 已全量预生成 + boot 回填）与既有 useWaveform hook（含 WebAudio 兜底与模块级缓存）；从 timeline 波形组件提炼共享 `PeaksSvg` 纯渲染深模块，双端复用。peaks 缺失窗口期给加载骨架占位。
- **单例试听 hook**：同刻只播一个，切 work/卸载即停；v0.1.8 只做播放/暂停，波形点击 seek 不做。
- **卫生过滤**：前端分类前过滤管线内部文件（波形 sidecar、拼接清单等 pattern）——纯前端过滤，agent 经 bridge 的文件投影不受影响。此项必须与 TEXT snippet 卡同批落地，否则 snippet 会把波形 JSON 渲染成"素材内容"。
- **顺带修**：预览弹窗 text 分支从死链接卡升级为全文预览；MIME 表补 m4a/aac/flac/ogg（使音频 Range/seek 生效）。音频横条统一玻璃底色，波形即视觉签名（放弃渐变身份色）。

### S6 · Dive 分镜聚簇画布，档 B（约 5-6 人日）

- **useSceneClusters 纯函数深模块**：composition → 簇集合。簇成员 = scene 的 memberAssetIds ∪ generatedAssetIds（selectedAssetId 高亮为选用 take）；衍生资产沿 walkProvenance 祖先链归入祖先所在簇（兜底）；无归属者进"未归属"簇（默认折叠）。scene↔asset 的 canonical 关联 v0.1.6 已落库（ADR-012 原子性保证），无需新 schema。

- **性能**：开启 xyflow 内置视口裁剪（onlyRenderVisibleElements）；视频节点用 IntersectionObserver 门控 preload，视口外不拉 metadata。
- **交互范围（用户拍板：只读全貌 + 重绑）**：保留现有 USE THIS 换 take；不做画布拖上 timeline、不做画布内重生成——感知层不做生成驾驶舱（对齐 ADR-012 否决过的方向）。

  - 素材分类过滤 + PeaksSvg（先例：LibraryTab 既有测试断言同步更新）；
